# Repository review — 2026-10-26

## Scope and evidence

The cloud review inspected the generator and CSV contracts, local quality gate,
transactional PostgreSQL loader and SQL constraints, commercial calculations,
forecast selection, promotion estimators, risk labels, authored Q4 ledger,
candidate orchestration, review packaging, dashboard scripts and setup/review docs.
The existing package structure separates analytical inputs from validation-only
latent-demand files; a structural rewrite is not needed for the current offline
synthetic analytics workflow.

Current-run evidence is generated by `scripts/run_candidate.py` in
`output/candidate_status.json`, `output/release_status.json`,
`output/test_summary.json`, `output/data_quality.json` and the stage logs.
Read those files for actual outcomes and counts rather than treating a historical
README or CI result as certification of this checkout. The source inventory
includes uncommitted file contents by hash; this review does not publish a new CI
result or deployment.

## Corrections

- Candidate status now records SHA-256 and byte-size inventories of build inputs
  and selected data/report artifacts. Input changes during execution fail the
  candidate and remove its navigation page. Review packaging rejects old builds
  without provenance and files changed, added or deleted since the completed run.
  This is change detection, not a signed authenticity guarantee. Regression tests
  exercise changed source/configuration, altered outputs and missing provenance.
- A zero product case size previously raised `ZeroDivisionError` during order
  validation. It now reports failed DQ rules. Positive case size, MOQ and store
  size checks align local validation with PostgreSQL constraints. Malformed JSON
  manifest container shapes now produce DQ-16 failures instead of attribute errors.
- Historical pre-merge candidate wording was updated to reflect the documented
  integration into main. Historical acceptance counts remain historical.
- CI now also runs the existing offline M2–M5 dashboard rendering/filter checks,
  alongside the existing Q4 filter checks.

These corrections do not change the generator, authored scenarios, money formulas,
forecast selection or business results. Rebuild all artifacts after applying them.

## Interpretation boundaries

- All observations are synthetic. Exact satang arithmetic, ledger reconciliation,
  checksums and repeat generation support internal consistency and reproducibility;
  they do not establish real-market accuracy.
- M3 method selection uses two fixed historical backtests. It is model-selection
  evidence, not an untouched final test of the selected model or a future guarantee.
- B1/B2 estimate observed promotion effects under their stated assumptions. The
  default calendar has no clean B2 controls; the staggered comparison is separate.
  Stock censoring and confounding limit causal interpretation.
- The receipt-aware rule trades fewer false positives for worse recall and PR-AUC
  in its reserved synthetic cohort. It is not demonstrated to dominate the baseline.
- Q4 incrementality, receipt timing, capacity and price assumptions are authored.
  Added SI may become stock; it does not establish consumer sell-through or profit.
- Automated DOM execution checks rendering and filters. Human visual review in an
  actual browser remains a separate step, recorded with `DEMO_REVIEW.md`.

No data adjustment is justified merely to improve model metrics or close the target
gap. Production APIs, real-data ingestion and broader deployment require their own
contracts and validation and are outside this review.
